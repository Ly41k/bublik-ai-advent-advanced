Добавь в Bublik Task Service endpoint PATCH /tasks/{task_id}/status.

Следуй действующим инструкциям проекта. Используй skill $quality-gate:
repo_root — фактический текущий корень проекта;
report_path — local-evidence/quality-gate.txt.
Для проверки архитектуры вызови настроенного architecture_report
(ArchitectureReportAgent) с полными обязательными входами по его контракту.
Передай фактический корень проекта, спецификацию этой задачи, изменённые
исходные файлы как review_scope и AGENTS.md как architecture_rules.

Контракт endpoint:
- task_id — UUID;
- тело запроса содержит ровно одно поле status;
- допустимые значения status: "todo" и "done";
- разрешено изменение в обоих направлениях;
- повторная установка текущего статуса успешна;
- успех: HTTP 200 и объект с полями id, title, status;
- изменение сохраняется и видно через GET /tasks/{task_id};
- id и title сохраняют исходные значения;
- неизвестный корректный UUID: HTTP 404,
  тело {"detail":"Task not found"};
- некорректный UUID, отсутствующий status, недопустимый status,
  null, неправильный тип status или лишнее поле: HTTP 422;
- невалидный запрос не меняет сохранённую задачу;
- изменение одной задачи не меняет другую.

Изменяй статус через application service и интерфейс репозитория.
Существующие сценарии должны продолжать работать.
Добавь сервисные и API-тесты успешного изменения, повторной установки,
неизвестной задачи и невалидного ввода. Существующие тесты сохраняй неизменными.

Не изменяй Rules, конфигурацию, зависимости, scripts/, gate2/ и evidence.
Разрешено изменять src/ и добавлять новые test_*.py в tests/.
Не выполняй внешние запросы и операции Git-публикации.
Не задавай уточняющих вопросов. Не обращайся к результатам другого прогона.

Запусти:
python -m compileall -q src tests scripts
python -c "from bublik.main import create_app; create_app()"
python -m ruff check .
python -m ruff format --check .
python -m pytest -q

В конце сообщи изменённые файлы, результаты проверок,
результат архитектурного субагента и оставшиеся проблемы.
